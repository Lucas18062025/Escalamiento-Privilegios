🐧 Mitigaciones en Linux
Cada vector de ataque tiene una contramedida. Implementa estas configuraciones para reducir drásticamente la superficie de ataque.
Configuración de Sudo ▼
Restringe sudo al mínimo indispensable. Evita NOPASSWD y usa reglas granulares.
# /etc/sudoers — usar visudo para editar Defaults env_reset, timestamp_timeout=5 Defaults logfile="/var/log/sudo.log" %admin ALL=(ALL:ALL) ALL # NUNCA: usuario ALL=(ALL) NOPASSWD: ALL # NUNCA: usuario ALL=(root) NOPASSWD: /bin/bash
Acciones: Audita /etc/sudoers y /etc/sudoers.d/* regularmente. Elimina reglas NOPASSWD innecesarias.
Binarios SUID/SGID ▼
Minimiza los binarios con bit SUID. Usa capabilities granulares en su lugar.
# Buscar todos los SUID $ find / -perm -4000 -type f 2>/dev/null # Eliminar SUID innecesario $ chmod u-s /usr/bin/some_binary # Reemplazar por capability específica $ setcap cap_net_bind_service=ep /usr/bin/myapp
Acciones: Revisa mensualmente. Elimina SUID de binarios que no lo necesiten. Usa AppArmor/SELinux para restringir.
Kernel y Parches ▼
Mantén el kernel actualizado. Los exploits de kernel son comunes en CTFs y entornos desactualizados.
$ sudo apt update && sudo apt upgrade -y $ sudo apt install unattended-upgrades $ sudo dpkg-reconfigure -plow unattended-upgrades $ sudo reboot
Acciones: Activa actualizaciones automáticas de seguridad. Monitorea CVEs del kernel con linux-exploit-suggester en modo defensivo.
Permisos de Archivos Críticos ▼
$ ls -la /etc/passwd /etc/shadow /etc/sudoers -rw-r--r-- 1 root root /etc/passwd -rw-r----- 1 root shadow /etc/shadow -r--r----- 1 root root /etc/sudoers $ chmod 644 /etc/passwd $ chmod 640 /etc/shadow $ chmod 440 /etc/sudoers $ chown root:root /etc/passwd /etc/shadow /etc/sudoers
Acciones: Audita permisos de /etc/passwd, /etc/shadow, /etc/sudoers, cron scripts, y directorios en PATH.
Docker y Contenedores ▼
Nunca des grupo docker a usuarios no administradores. Es equivalente a root.
$ gpasswd -d usuario docker $ chmod 660 /var/run/docker.sock $ chown root:docker /var/run/docker.sock # En Dockerfiles, NUNCA correr como root: USER 1000:1000
Acciones: Usa rootless Docker. Restringe el socket. Audita membresías del grupo docker.
🪟 Mitigaciones en Windows
Windows tiene vectores únicos. Estas configuraciones reducen la superficie de ataque significativamente.
Privilegios de Usuario ▼
Restringe privilegios peligrosos como SeImpersonatePrivilege para cuentas de servicio no confiables.
PS C:\> Get-LocalUser | Where-Object {$_.Enabled -eq $true} PS C:\> Get-LocalGroupMember -Group "Administrators" PS C:\> whoami /priv # Remover SeImpersonatePrivilege de cuentas de servicio innecesarias PS C:\> secedit /export /cfg C:\security.cfg
Acciones: Principio de mínimo privilegio. Usa Managed Service Accounts (gMSA) para servicios. Audita privilegios con accesschk.exe.
Servicios: Rutas con Comillas ▼
Todas las rutas de servicios deben estar entre comillas dobles para prevenir Unquoted Service Path.
PS C:\> sc qc "VulnService" BINARY_PATH_NAME : C:\Program Files\Vuln App\service.exe PS C:\> sc config "VulnService" binpath= "\"C:\Program Files\Vuln App\service.exe\"" [SC] ChangeServiceConfig SUCCESS
Acciones: Audita todas las rutas de servicios. Corrige las que no tengan comillas. Usa PowerUp en modo defensivo.
Parches y Actualizaciones ▼
PS C:\> Install-Module PSWindowsUpdate -Force PS C:\> Get-WUHistory PS C:\> Get-WUInstall -AcceptAll -AutoReboot PS C:\> wmic qfe get Caption,Description,HotFixID,InstalledOn
Acciones: WSUS/SCCM para parches centralizados. Audita parches faltantes con windows-exploit-suggester.
AlwaysInstallElevated ▼
Esta configuración permite que cualquier usuario instale MSI con privilegios de SYSTEM. Debe estar deshabilitada.
PS C:\> reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated PS C:\> reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated # Si existe y es 0x1, eliminar: PS C:\> reg delete HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated /f PS C:\> reg delete HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated /f
AppLocker / WDAC ▼
AppLocker o Windows Defender Application Control (WDAC) pueden prevenir la ejecución de binarios no autorizados.
PS C:\> Get-AppLockerPolicy -Effective | Format-List PS C:\> Get-WdacPolicy -PolicyType Base
Acciones: Implementa reglas de AppLocker para restringir ejecución en directorios escribibles por usuarios (C:\Users\Public, C:\Windows\Temp, etc.).
📋 Principios Generales de Defensa
Estas prácticas aplican a cualquier sistema operativo y son la base de una postura defensiva sólida.
🔒 Principio de Mínimo Privilegio
Cada usuario, servicio y aplicación debe tener únicamente los permisos estrictamente necesarios para su función. Nada más.
📊 Segmentación de Red
Separa redes por función. Un compromiso en la DMZ no debería permitir acceso a la red interna crítica.
🔍 Logging y Monitoreo
Centraliza logs de autenticación, ejecución de procesos, y cambios de permisos. Usa SIEM para correlacionar eventos.
🔄 Actualizaciones Automáticas
Aplica parches de seguridad tan pronto como estén disponibles. Los exploits públicos aparecen días después del parche.
🛡️ Estrategia de Defensa en Profundidad

  • 3Host: EDR, HIDS, hardening del SO
  • 4Aplicación: Secure coding, SAST/DAST
  • 5Datos: Cifrado en reposo y tránsito, DLP
  • 6Identidad: MFA, PAM, gestión de secretos
